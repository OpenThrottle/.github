# Contributing to OpenThrottle

Thanks for your interest in contributing! This is the **organization-wide
default** guide that applies to OpenThrottle repositories which don't ship their
own `CONTRIBUTING.md`. A repository that provides its own contribution guide
overrides this default for that project — always follow the repo-local guide
when one exists.

## Ways to contribute

- **Issues** — report bugs or request features using the repository's issue
  templates. Search first, then include clear reproduction steps.
- **Pull requests** — for anything beyond a small, obvious fix, open an issue to
  discuss the approach before you build it.
- **Questions** — open an issue for clarification.

## The basics

1. **Fork or branch**, then make your change on a feature branch — never commit
   directly to the default branch.
2. **Follow the repository's conventions** — check its `README.md` for how to set
   up, build, and test. Run the project's checks locally before opening a PR.
3. **Use [Conventional Commits](https://www.conventionalcommits.org/)** for
   commit messages where the repository enforces them.
4. **Open a PR** with a clear description and testing steps.

## Contributor License Agreement

Inbound contributions to OpenThrottle projects are governed by a **Contributor
License Agreement** (individual and corporate). A maintainer will point you to
the signing process on your first contribution where it applies.

## Community expectations

- **Code of Conduct** — participation is governed by our
  [Code of Conduct](./CODE_OF_CONDUCT.md).
- **Security** — never report vulnerabilities in public issues; follow
  [SECURITY.md](./SECURITY.md).
